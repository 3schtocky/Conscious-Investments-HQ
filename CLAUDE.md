# CLAUDE.md: Conscious Investments HQ

You are building (and later maintaining) an AI-run stock-picking office for **Conscious Investments**, owned by Ethan Stott ("the Captain"). The plan of record is `~/.claude/plans/i-want-to-create-quiet-adleman.md`.

## Build rules
1. **Phase gates.** Work in the plan's phases. At the end of each phase run `uv run pytest`, `uv run ruff check hq tests`, `/code-review`, report API spend for the phase, demo it, then **stop for Ethan's approval** before starting the next phase. Ethan asked for these pauses explicitly.
2. **Ask with prompts.** Put decisions for Ethan in AskUserQuestion prompts (multiple choice, recommended option first), not in prose lists.
3. **API credits only when absolutely necessary (Stott, 2026-09-29).** Build, test, review, demo and run erb on the Claude Pro subscription (Claude Code). The office's own agents are the only thing that spends API credits, and they are locked behind the master switch `api.enabled` in `config/office.yaml`, which is **false** by default: every real call (`AnthropicClient`, the LLM tone filter, `hq smoke`, `hq run-agent`) passes `hq.engine.llm.require_api()` and stops at $0 while it's off. Never flip it yourself. A real run needs (a) a cost estimate, (b) Stott's explicit yes for that specific run, (c) Stott switching the API on, and (d) switching it back off and reporting the spend (to the cent) right after. Verify everything with mocked tests (`tests/conftest.py` FakeLLM) and `hq serve --demo`; phase gates skip real checks unless Stott asks. The tone filter defaults to the free rule-based rewriter (`tone.engine: rules`). Also count as spend: scheduled or looping runs, A/B tests, per-wing go-live checks. Default to none of them.
4. **Public repo.** Never commit `.env`, `data/`, `memory/`, `outbox/`, chat logs, or anything under `Equity Research/coverage` or `reference/`.
5. **erb lives in the submodule.** Change erb in `Equity Research/` with its own tests and commits, push to its repo, then bump the submodule pointer here. erb keeps its own CLAUDE.md and guardrails (sourcing, the model makes the numbers, style lint).

## Office design (summary)
- Engine: Anthropic Python SDK, our own streaming tool-use loop. Leads (Quill, Scout, Sigma, Vera, Harbor) on `claude-sonnet-5-5`, effort high, summarized thinking. Associates (Ledger, Pip, Delta, Tally, Wren) and Juno on `claude-haiku-4-5`. Leads hand narrow jobs to associates with `delegate` and get a compact structured summary back.
- Quant Department (Sigma, Delta) owns every price target. Each wing's way of thinking lives in `departments/<wing>/` (charter, playbook, lessons; see `departments/README.md`), loaded by `hq/departments.py`. No company facts in those files. Only Stott-approved, versioned models are the firm's numbers.
- Agent-facing text says `{captain}`, filled from the roster's captain nickname (Stott).
- Budget: `config/office.yaml`. The daily cap is checked before every model call. At the cap, in-flight steps finish and the office clocks out.
- The office only works when the Captain assigns work. Captain messages go through a tone preview (original kept in the log; instructions, numbers and tickers must survive the rewrite).
- Audit: Tally's checks are plain code in `hq/audit.py` and run for free on every approval card and finished assignment (flags and notes). Vera is called in only on flags, or when the Captain sends her a finding. She can pause one colleague at a time and alert the Captain; only the Captain unpauses, and a pause survives a restart.
- Final audit (`hq/sourcemap.py`, `hq/finalaudit.py`; `uv run hq final-audit TICKER` is the free read-only check): `documents` gathers a ticker's finished deliverables (memo, brief, Model Brief, initiation report, newsletters naming it), `source_pool` the numbers in its real sources (approved model, Model Brief, facts, filings, notes); `sourcemap.tie_out` matches every figure with rounding and scale (units, thousands, millions) and clears matches for free. `run` records one `unsourced_figure` flag per failed sentence under the owner and calls Vera. Vera's `request_redo` sends only the upheld parts to each owner as a fresh `Audit redo:` task; `audit_redos` counts rounds per part (doc|section|figure); after `MAX_REDOS` (2) a part becomes an incident for the Captain. `Office.audit_task` calls `after_redo`, which re-checks and clears what now ties out. `maybe_offer` files a "Ready for final audit" card (approval kind `final_audit`); nothing is offered automatically yet. Gaps: derived figures need Tally to trace, and no UI button yet.
- Office memory: a desk note passes the code screen (`hq.audit.screen_note`) or waits for the Captain; wiki changes always wait for the Captain. The daily audit digest is compiled by code, never by a model call.
- Client Relations: Wren drafts and Harbor finalizes the weekly newsletter and client memos into `outbox/`. `hq/outbox.py: check_issue` is the code gate (only approved numbers, watchlist names as ideas only, no hype or advice); a failing issue can't be finalized. `hq/publish.py` holds the Publisher interface; the only publisher writes ready-to-paste files and never posts anything.
- Client outreach (`hq/outreach.py`, tools in `hq/tools/client.py`): Client Relations' second function. On the Captain's request Wren drafts and Harbor finalizes a one-to-one email from contact@consciousinvestments.org about the weekly note and the live office. `check_email` is the code gate (valid address, segment, a stated reason, not suppressed, 14 days between emails and 3 in all, our own links only, no hype or advice, approved numbers only, a warning for individual investors); the footer (address, opt-out, disclaimer) is built by code; `client_relations.outreach.postal_address` must be set before anything can be finalized. Approval re-runs the gate against today's facts, then `hq/publish.py` `DraftMailer` marks it ready for the Captain to send himself (Phase A). Phase B adds a Resend mailer behind the same interface (still only after approval). `suppress_contact` records opt-outs in `outbox/outreach/suppressed.json`. Outreach events are not in the public stream, and `/outbox` is Captain-only.
- Model Brief and hand-off (`hq/modelbrief.py`, `hq/handoff.py`, tools in `hq/tools/brief.py`; Client Relations' slidedeck, phase A of the department build): for an approved model, code computes the facts (targets, method values, drivers by swing, sensitivity, Monte Carlo) and Quant writes the reading (`save_model_brief`, dollar figures must be the facts' own); `read_model_brief` is Quant's and, once ready, Client Relations'. `handoff.readiness` needs an approved Outperform model, a finished `*Initiating-Coverage*` report in the coverage folder and a ready brief; then code files a `handoff` approval card ("Ready for Client Relations", author `office`) on a model approval, a saved brief or any finished assignment (`handoff.scan`). Approval re-checks the conditions and gives `cr_lead` the outline assignment; declining starts nothing. Slidedeck, phase B (`hq/deck.py`, `hq/deckbuild.py`, tools in `hq/tools/deck.py`): 17 fixed slides (`deck.SLIDES`), some filled by code from the approved model's Model Brief facts (call, drivers, forecast, valuation, sensitivity, simulation, what-would-prove-us-wrong, assumptions, sources, disclosures) and some written by Wren (thesis, business, mispricing, peers, catalysts, risks: headline, 3 to 5 bullets each naming a `report:<section>` or `brief:<part>` source, notes). `deck.check_copy` is the gate: every figure must exist in the report sections, the brief facts or the report's model.json (`deck.untraceable`), the newsletter gate's rules (approved targets, hype, advice) plus the playbook's hype words, risk words at least 0.9 of upside words, and the report's targets must equal the approved model's. Typography (Stott's rules): bullets and headlines carry no closing punctuation (the gate refuses a bullet or detail ending in . ; : or ,, and the builder strips it from headlines and code-built bullets); no paragraph ends on a stub line (`hq/deckwrap.py` measures with the real Calibri/Georgia files, simulates PowerPoint's wrap and inserts an explicit line break so the last line holds at least 3 words; PowerPoint ignores non-breaking spaces, so those don't work). Tools: `slidedeck_material`, `save_slidedeck_copy`, `read_slidedeck_copy`, `build_slidedeck` (both CR agents). Output: `outbox/decks/<T>/<date>/copy.json` and `CI_<Company-Name>_<T>_Slidedeck_<date>.pptx` (named like the report: the company part is copied from the report's own file name by `deck.file_stem`) (native python-pptx charts and tables, speaker notes). Tested on the real Micron report (`tests/fixtures/deck_mu_copy.json`); rendered through PowerPoint to check layout. Phase C (`hq/deckpack.py`, `finalize_slidedeck` for `cr_lead`): `package` rebuilds the slidedeck from today's clean copy, ties EVERY figure printed on every slide (code-built ones too) to a source with Audit's `hq.sourcemap` and `finalaudit.source_pool` (an unmatched figure stops the package; `CI_<Company-Name>_<T>_Source-Map_<date>.md/.json` are written either way), exports the PDF through PowerPoint (AppleScript, `deckpack.export_pdf`, no PDF if PowerPoint is absent) and writes `outbox/decks/<T>/<date>/meta.json`. `finalize_slidedeck(ticker, issue?)` also prepares the matching newsletter issue (same `publisher.prepare`) and files ONE `deck` approval card for both. Approval (`Office._deck_decided`) re-gates the copy, the approved model's version and rating, the report and the brief, and the newsletter, and is refused with the reason if any moved; a decline is always allowed. Nothing is sent. Outbox tab has an "Slidedecks" section; decks are Captain-only (`/outbox/` is private).
- Paper portfolio (`hq/portfolio.py`): only approved Outperform names, sized 3, 5 or 8 percent; a paper fill at the latest price when the Captain approves; code raises exit cards (base target reached, rating below Outperform, down 25 percent) and the Captain decides. Mark-to-market and the scoreboard against SPY are plain code on free Yahoo quotes. No real money moves.
- Pause office (button by the spend meter; `Office.hold` / `release`): steps in flight finish, then no agent takes a turn except to answer a message the Captain sends that agent directly (one message, one turn, plain-text reply delivered to him, only read tools allowed). An answer never ends the task it interrupted. The pause survives a restart.
- Messages and stuck work: a task the Captain gives directly never ends in silence (`Agent._report_unreported` delivers a plain-text answer if the agent sent no report). Juno has `read_office` (who is doing what, unfinished work, cards, incidents; no costs) and `assign_task` takes one lead, a list, or `all_leads`. Guard-paused tasks (turn cap, loop, cost cap) and API problems (`hq.engine.llm.api_problem`: out of credit, bad key, rate limit, overloaded) show an incident with a Resume button (`Office.resume_from_incident`); a resume gets a fresh allowance of turns and spend. A context-cap task or a delegated job can't resume.
- Agent communication (leads build, delegates talk): each wing's delegate (its associate) is the wing's head of communication. `hq/digest.py` builds a per-wing activity digest from the event log by code (tools used, files written, delegations, turns, blockers, cards waiting on the Captain; no model call, no costs, works while paused). A lead's `send_message` reaches only its own delegate, Juno or Audit (`hq/tools/comms.py: check_route`); a delegate may not message another wing's lead directly. Delegates run a separate Haiku comms loop (`hq/engine/comms.py`, task kind `comms`, prompt `prompts/comms.md`, own turn and $0.05 limits) beside any job in hand, so a busy delegate still answers. Tools: `wing_status`, `ask_delegate` (answer comes back as reply text, one hop only), `relay_request` (becomes an assignment for the other lead, answered back through the delegates). Announcements go to delegates, who reply once for the wing; leads hear them (inbox, or with their next assignment via `Office.bulletin`) but are not asked to reply. Audit and Juno are exempt from the routing rule. When a comms exchange cannot run (paused, API off, budget) the answer is the digest read out by code, or the message queues in the old way.
- Juno's rounds (`hq/rounds.py`): she walks to each busy wing's delegate, asks where it stands, and builds a roll-up (no model call of her own). A timer (`rounds:` in office.yaml, defaults in code: every 120s, post to the Captain on change and every 3rd round, walk pause 1.2s; the committed config has no `rounds:` block, so defaults apply) runs while work is going; while the office is paused she walks only when something changed and the roll-up is read from the digest at $0. `walk_the_floor` is her on-demand tool (allowed in a pause; an agent that looks something up during a pause gets up to two reading turns for that message). The Rounds sidebar tab (`web/src/ui/rounds.ts`, `GET /api/rounds`, `POST /api/rounds/walk`) is Captain-only; visitors see her walking, never the text.
- Turn economy: file tools forgive `EOSE/facts/...` and `coverage/EOSE/...` paths, a wrong file name comes back with the closest real ones, one read is capped at 20,000 characters, and `search_file` finds a line in a long filing without paging. `submit_result` accepts open questions as text or objects and findings up to 16,000 characters. The identical-call loop guard resets after a state-changing tool (`STATE_CHANGING` in `hq/engine/guards.py`), so rebuilding a model after editing its assumptions is not a loop.
- Demo office (`hq/demo.py`): scripted scenes plus an improviser that answers whatever the Captain types from real office data (status questions use `read_office` and the task record, "team"/"everyone" goes to `all_leads`, tickers are picked out of the request, a standing instruction is acknowledged rather than researched, announcement replies vary by role). Spoken lines carry no "(demo)" tag, since the Demo button's tooltip says it once (the old DEMO pill is gone); artifacts a visitor could mistake for real work (newsletter, watchlist thesis, card and task titles) keep it. The memo scene rotates fictional companies.
- Visitor replay (`pub.replay`, `GET /api/public/replay`, `web/src/ui/replay.ts`): when the floor has been quiet for ~12 seconds a visitor's page plays back the latest real stretch of floor activity (up to 150 events, at most 7 days old), marked by a "Replay" pill and banner; any live event stops it and restores the true state. Every replayed event goes through `pub.event`, the same filter as the live stream, so a replay never shows more than watching live. `GET /api/public/health` says only whether the office answers.
- Going live (`hq/deploy.py`, guide in `deploy/README.md`): `hq go-live` is the readiness checklist, `hq rehearse` runs the scripted demo office public through a throwaway `*.trycloudflare.com` address (`server.REHEARSAL_SUFFIX`, set only by that command, makes the address count as the public site for that run), `hq service-files` writes launchd files under `data/service/` (office under `caffeinate`, plus the tunnel; nothing is installed for the Captain, he runs the printed commands). `deploy/worker.js` is a Cloudflare Worker that shows `deploy/offline.html` when the office is down; `python3 deploy/bake.py` re-bakes it and a test fails if they drift. Visitors who lose their connection see a "Reconnecting" banner.
- Micron demo (`hq export-demo-micron`; `hq/demo_micron.py`, `hq/demo_script.py`, `hq/demo_export.py`; player `web/src/ui/demoTour.ts`): a Demo button in a visitor's header plays a recorded run in their own browser from 0:00 (about 5:40, seven acts, restart any time). The run is the real engine on a throwaway DB with scripted words: Juno assigns, Research and Quant work in parallel (real `build_model`, `run_simulations`, `erb_lint`), Stott approves the model, Audit checks the report against it, Client Relations' note passes `check_issue`, then the team proposes, Audit checks and Stott approves a 10% paper position (a demo-only size: `portfolio.SIZES` is widened only while recording; the real office stays 3, 5, 8). Agents are named by `{role_id}` placeholders so renames still work. Words reach visitors only through the exported `web/public/demo/micron/tour.json`; the live public stream and replay still mask them. The report is the real erb initiation in `Equity Research/coverage/MU` (Outperform, base $1,242.41 on the Street's revenue); rebuild it, then re-run the export. Deliverables (report, model, note, DOCX/XLSX/PDF downloads, the Gems-style position card on the Portfolio tab) ship as static files under `/demo/micron/`.
- Nothing is published or entered into the paper portfolio without the Captain's approval.
- Public mode (`hq serve --public`, behind a Cloudflare Tunnel): the Captain signs in with `HQ_CAPTAIN_PASSWORD`; everyone else is a visitor who gets only the sanitized views in `hq/public.py` (floor movement, watchlist, portfolio scoreboard, approved newsletters). Visitor access is deny-by-default: a new endpoint is private unless added to `visitor_allowed`, and `tests/test_public.py` checks every route and plants secrets to prove nothing leaks. In local mode the server only answers its own page on this machine (`request_allowed`).

## Conventions
- Python 3.12 via `uv`; run everything with `uv run ...`.
- Show every cost to Ethan rounded to the cent ($0.00), in the UI, the CLI and gate reports. The ledger stores full precision so the daily cap stays exact.
- Costs come from `hq.engine.ledger.usage_cost` and the pricing table in `office.yaml`. Update the table when prices change.
- Use the exact model ids from `office.yaml`. Haiku 4.5 takes `thinking: {type: "enabled", budget_tokens: N}` and has no `effort`. Sonnet 5.5 takes `thinking: {type: "adaptive", display: "summarized"}` and `output_config.effort`.
